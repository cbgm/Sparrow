# SecureChat control plane

The control plane contains only the shared SecureChat services:

- signed node registry
- presence directory
- push / FCM
- PostgreSQL and Redis persistence
- Caddy edge proxy

It does not contain gateway, federation, or mailbox services.

## Deployment bundle

The `Server Images` workflow creates a ready-to-run control-plane artifact. After extraction,
`Start-SecureChatControlPlane.cmd` is at the artifact root.

There is one editable configuration file:

```text
securechat.conf
```

Default LAN configuration:

```properties
MODE=lan
PUBLIC_DOMAIN=
SECURECHAT_IMAGE_PREFIX=ghcr.io/<owner>/securechat
SECURECHAT_IMAGE_TAG=<generated-tag>
```

The control-plane configuration intentionally has no `CONTROL_PLANE_URLS`. A control plane does not
point at itself or at other control planes. The list of available control planes belongs to each
community node.

`SECURECHAT_IMAGE_PREFIX` and `SECURECHAT_IMAGE_TAG` are generated by CI and normally should not be
changed.

## LAN mode

```properties
MODE=lan
PUBLIC_DOMAIN=
```

Double-click `Start-SecureChatControlPlane.cmd`. The existing LAN edge remains on port `8390`.

## Public Internet mode

```properties
MODE=public
PUBLIC_DOMAIN=cp1.example.com
```

If `PUBLIC_DOMAIN` is blank, the launcher detects the public IPv4 address and derives an sslip.io
hostname such as `203-0-113-10.sslip.io`.

Public mode adds `docker-compose.production.yml` and exposes Caddy on ports 80/443. A local HTTP
listener remains bound to host loopback port `8390` so local emulator access and launcher health
checks continue to work.

The `secrets/` directory must contain `firebase-admin.json`. Database passwords and the internal
push token are generated automatically and preserved there.

Ports 80 and 443 must actually reach the host. The launcher cannot change router NAT or external
cloud-firewall rules.
