# Standalone SecureChat community node

A community node is the independently hostable SecureChat data plane:

- gateway
- federation
- mailbox
- mailbox PostgreSQL
- federation PostgreSQL
- Caddy

It does not contain push/FCM or control-plane credentials.

## Deployment bundle

The `Server Images` workflow creates a ready-to-run community-node artifact. After extraction,
`Start-SecureChatNode.cmd` is at the artifact root on Windows.

There is one editable configuration file:

```text
securechat.conf
```

Default LAN configuration:

```properties
MODE=lan
PUBLIC_DOMAIN=
CONTROL_PLANE_URLS=http://192.168.178.60:8390
SECURECHAT_IMAGE_PREFIX=ghcr.io/<owner>/securechat
SECURECHAT_IMAGE_TAG=<generated-tag>
```

`SECURECHAT_IMAGE_PREFIX` and `SECURECHAT_IMAGE_TAG` are generated by CI and normally should not be
changed.

`CONTROL_PLANE_URLS` accepts multiple entries in priority order:

```properties
CONTROL_PLANE_URLS=https://cp1.example.com,https://cp2.example.com,https://cp3.example.com
```

The node keeps all configured control planes in priority order, tracks reachability at runtime,
and automatically switches to another reachable control plane without a node restart. Registration,
heartbeats, and presence publication are synchronized across the configured control planes.

## LAN mode

```properties
MODE=lan
PUBLIC_DOMAIN=
CONTROL_PLANE_URLS=http://192.168.178.60:8390
```

The node automatically advertises the machine's LAN address on port `8490`.

Windows: double-click `Start-SecureChatNode.cmd`.

Linux: run `start-securechat-node.sh`.

macOS: double-click `Start-SecureChatNode.command`.

## Public Internet mode

```properties
MODE=public
PUBLIC_DOMAIN=node1.example.com
CONTROL_PLANE_URLS=https://cp1.example.com,https://cp2.example.com
```

If `PUBLIC_DOMAIN` is blank, the launcher detects the public IPv4 address and derives an sslip.io
hostname such as `203-0-113-10.sslip.io`.

Public mode adds `docker-compose.production.yml`, exposes Caddy on ports 80/443, and advertises:

```text
wss://<PUBLIC_DOMAIN>/relay
https://<PUBLIC_DOMAIN>
```

Ports 80 and 443 must actually reach the host. The launcher cannot change router NAT or external
cloud-firewall rules.

## Local generated state

The launcher creates these automatically and they are not user configuration:

```text
.env.runtime
secrets/
```

Keep the Docker volumes and `secrets/` directory when updating an existing node. Deleting the node
identity volume creates a new node identity and therefore a new registry node ID.
